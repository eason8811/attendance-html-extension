# 考勤明细 HTML 采集器

在 Chrome / Edge 桌面版侧边栏中，按页保存已登录考勤明细页面的当前 DOM 快照。扩展不请求隐藏接口、不更改查询条件，文件只写入用户选择的本地目录。

## 实现状态

- **P0**：WXT、React、TypeScript、Tailwind CSS v4、shadcn/ui、MV3 侧边栏和本地目录选择/授权/写入探针已实现。当前执行环境没有可用的 Chrome/Edge，因此 File System Access API 的实机授权、重启恢复和磁盘写入仍需人工验证。
- **P1**：目标 URL、页面结构、表格表头和分页信息识别已实现。原始本地 HTML 已确认解析为 1143 条、23 页、当前第 1 页、50 条/页。长期测试只使用脱敏 fixture，不包含原始样例。
- **P2–P4**：DOM + DOCTYPE 快照、每次任务独立目录、逐页写入、页码稳定检查、状态进度、取消和失败保留已实现，并由模拟页面驱动测试覆盖。真实登录页的翻页方式及连续 23 页落盘尚未实机验证。

`考勤明细.html` 可能包含员工个人信息，已加入 `.gitignore`。不要把它提交到公开仓库或复制进脱敏 fixture。

## 本地开发与校验

```sh
pnpm install
pnpm dev
pnpm check
pnpm lint
pnpm test
pnpm build
pnpm zip
```

生产构建输出在 `.output/chrome-mv3/`；ZIP 由 WXT 生成在 `.output/` 下。当前工程没有配置 Playwright 浏览器端到端测试；分页和任务调度由 Vitest 模拟驱动覆盖，实站与系统文件对话框需要在 Chromium 中人工确认。

## 加载未打包扩展

1. 运行 `pnpm build`。
2. 打开 `chrome://extensions` 或 `edge://extensions` 并启用开发者模式。
3. 选择“加载已解压的扩展程序”，指向 `.output/chrome-mv3/`。
4. 打开已登录的目标考勤明细页；安装扩展后若内容脚本尚未出现，刷新该业务页。
5. 点击扩展图标打开侧边栏。

## 采集流程

1. 在侧边栏选择一个本地目录，并按浏览器提示授予读写权限。
2. 可选：点击“写入测试文件”验证目录可写。探针只写纯文本，不包含考勤信息。
3. 确认“目标页面”显示已识别，并核对当前页与总页数。
4. 点击“开始采集”。如果页面当前不在第 1 页，扩展会先通过页面现有控件回到第 1 页。
5. 采集期间保持侧边栏打开，并让目标标签页保持活动。点击“取消采集”会停止后续翻页，已成功写入的文件会保留。

每次任务会在所选根目录下创建随机唯一的 `attendance-本地时间-随机后缀/` 子目录，并写入 `page-001.html`、`page-002.html` 等文件。只有文件写入流成功 `close()` 后，进度才会增加。HTML 内容是页面 JavaScript 执行后的当前 DOM 和 DOCTYPE；CSS、脚本、图片等资源不会一并下载。

## 权限范围

- `sidePanel`：打开采集器侧边栏。
- 内容脚本只匹配 `https://ncpc.ibuy.ccb.com:9092/member/techworkload/queryMonWorkLoadAttendanceDetails.htm` 对应页面。
- 目录句柄保存在扩展源的 IndexedDB；授权每次恢复后都会重新检查。扩展不读取 Cookie、不访问隐藏业务接口，也不上传页面数据。

Chrome 的匹配模式支持明确指定端口；不写端口时会按通配端口处理，当前项目将端口 `9092` 纳入匹配规则。[Chrome match patterns 文档](https://developer.chrome.com/docs/extensions/develop/concepts/match-patterns)

## 需要人工验证的浏览器行为

在用户自己的已登录 Chrome 或 Edge 中完成以下检查；不需要向扩展提供账号或密码：

1. 选择临时目录，确认随机探针文件出现；关闭并重开侧边栏、重启浏览器后确认目录名恢复，并按需重新授权。
2. 在目标页记录当前页后点击一次页面自己的“下一页”，观察 URL、文档导航、页码摘要和表格行变化，以确认真实翻页是 AJAX、整页导航或其他行为。
3. 从非第 1 页启动一次采集，确认扩展回到第 1 页后才写 `page-001.html`；检查快照中的 DOCTYPE、当前页摘要和页码顺序。
4. 检查连续翻页、末页停止、取消、切换标签页和关闭侧边栏时的表现。实站页码或表格结构不稳定时，扩展应停止而不是继续保存。

静态 HTML 只证明页面标记结构，不足以证明真实翻页行为。当前适配器只点击页面现有页码链接或 `#pgnIpt` / `#pageGo` 控件，随后等待目标页码与表格内容稳定；这些控件在实站上的事件效果仍待上面的浏览器验证。

## 常见限制

- 采集仅适用于匹配的目标 URL 和可识别的页面结构。网站改版导致表格、分页选择器变化时，扩展会停止并显示结构错误。
- 目录选择依赖 Chromium 桌面版提供的 File System Access API；受管理策略限制的浏览器可能禁用该 API。
- HTML 快照不包含样式、图片、字体或脚本资源，离线打开时不保证与在线页面视觉一致。
- 当前版本不在侧边栏关闭后后台继续运行，也不支持跨会话断点续传。
